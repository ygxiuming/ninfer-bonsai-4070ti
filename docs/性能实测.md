# 性能实测数据

> 全部数字为实测，标注口径。跨卡数字不可比（带宽/SM 数不同），
> 跨引擎版本同理——对比请用同一次运行内的相对值。

## 0. A3 引擎更新口径（2026-09-27 深夜：pkg2 r12 树 + P1/P2/A3 补丁 + SM_COUNT=60）

| 项 | 旧树（2026-09-26） | A3 树（r12 + SM_COUNT=60） |
|---|---|---|
| prefill（3.6k tok 提示） | 1759 t/s | **2191 t/s（+24.57%）** |
| decode（同任务，K=2） | 85.9 t/s | 86.0 t/s（中性） |
| 输出 sha | 880f7371… | **逐位一致**（pkg5 token grid 无损门） |
| 前缀复用 | 账本 bug → --no-prefix-reuse | **修复，默认开**（第二请求 86 t/s 缓存命中） |
| 高可预测任务 decode | ~85 t/s | **K=3 145 / K=5 173 tok/s**（接受率 88~99%） |

> 依据：verify-20260927-224958.json（A/B 交替执行、丢弃首轮取中位、sha 逐位门）
> 与 start-ninfer.sh v3 实测注释。接受率强依赖任务：数数/模板/照抄类 88~99%，
> 说明文/对话类 28~40%（此时 ~80 t/s 是正常水平）。环境变量
> `NINFER_TERNARY_SMALL_T_ROWS=16` 必配（32 行档有 PTQ1_0 PPL 缺陷）。

## 3. 预填吞吐曲线（预填是新版引擎的最大收益）

| 提示长度 | prefill | TTFT |
|---|---|---|
| ~1k tok | 1775 t/s | 397 ms |
| ~4k tok | 1837 t/s | 1491 ms |
| ~8k tok | 1823 t/s | 2973 ms |
| ~16k tok | 1780 t/s | 6041 ms |
| ~32k tok | 1694 t/s | 12670 ms |

> 1k→32k 只衰减 5%。旧版引擎（CraneBW/zatfung）同口径 1020~1086 t/s
> ⇒ **新版 prefill +79%**，TTFT 从 ~450ms 降到 ~190ms。

## 4. 上下文与解码

| 场景 | decode |
|---|---|
| 空上下文（短提示） | 76.7 t/s |
| 32k 上下文填满 | 83.9 t/s |
| 112k 上下文（long 档） | 启动富余 251MB，可运行 |

上下文上限实测（fp8 + MTP K=3）：**112k** ✅ ／ 131k 差 370MB ⛔ ／ 262k 需 9.2GB ⛔。
KV 密度实测：fp8 ≈ 33-35 KiB/token，int8 ≈ 43，rk4v4 ≈ 17-24。

## 5. MTP 投机解码（K 扫描，essay 任务，greedy）

| K | decode | 接受率 | 逐位置接受率 |
|---|---|---|---|
| 1（关） | ~52 | — | — |
| 2 | 80.9 | 51.8% | — |
| **3** | **83.9** | 42.6% | **← 日常最优** |
| 4 | 79.8 | 33.2% | — |
| 5 | 76.6 | 27.7% | 83/44/25/15/5（/163 轮） |

> K=5 逐位置衰减陡峭（第 1 位 51% → 第 5 位 3%）。官方 4080S 的 226 t/s
> 口径为 5.48 tok/轮（~91% 接受率），交付源码树暂未包含其对应改动
> （官方二进制比源码快照新 3KB）。⇒ 日常用 K=3。
